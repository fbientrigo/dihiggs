# T4 integration report

## Scope and route contract

The [orchestration API](../../dihiggs/app/orchestrator/analytic_bridge.py) defaults to `mode="legacy"`. The additive production CLI supports `--engine t4 --t4-mode legacy|explicit|analytic --point-json ... --output ...`; existing engines retain their prior default and schemas. The bridge uses `THDM::set_param_phys` for legacy, `THDM::set_param_phys_lam1` for explicit, and `THDM::set_param_gen_exact` for analytic construction. Explicit and analytic modes match the requested electroweak scale through `SM::set_GF`; legacy keeps existing SM inputs. Nondegenerate reversed CP-even states are mapped to actual calculator indices and the target phase convention; raw and mapped states/couplings are retained. Exactly degenerate states return `INCONCLUSIVE` without decay calls.

The anchor comparisons use (mh=125.13 GeV, mphi=150 GeV, mA=mHp=200 GeV, tanβ=10^6, lambda1_ref=1.2, X=1, v=246 GeV). Full decimal and binary64 inputs, observable residuals, tolerances, spectra, and output spreads are retained in `T4_integration_report.json`.

## Calculator agreement

The analytic route passed all seven generic quartic, all seven Higgs-basis quartic, mass, vev, signed-coupling and complete-spectrum comparisons in each 50/80/120-digit trial under the separately declared per-observable tolerances. The complete four-block scattering spectrum matched the independent mpmath result within 9e-16; scalar masses differed by at most 1.6e-9 GeV. The signed hφφ coupling matched within binary64 precision and the signed φH⁺H⁻ coefficient differed by 2.4e-15 GeV. The requested and backend vevs were 246 and 245.99999999999997 GeV. This is a single high-tanβ anchor, not a scan-wide calculator certification.

The explicit lambda1-aware physical route matched the requested vev and had maximum quartic discrepancy 1.70e-11, above the 5e-12 declared bound. It reconstructed m12² with a 1.72e-7 GeV² discrepancy and tanβ with a 2.07e-5 discrepancy, so it remains FAIL at this anchor. The legacy physical route retained default SM vev 246.22056907348588 GeV and reconstructed quartics of order 4.34e8; it remains FAIL against the stable-family inputs.

The opt-in `set_param_gen_exact` method retains the generic route’s supplied m12² and tanβ for later calculator getters, avoiding the cancellation-prone reconstruction in `get_m12_2()`. It does not cache requested scalar masses: the bridge derives the spectrum from the supplied potential. The original generic and physical setter paths remain unchanged by default. The isolated campaign build recompiled all library translation units that depend on the THDM layout. The JSON report stores input serialization losses, backend residuals, 50/80/120 output spreads and the single-anchor measured numerical error budget separately from declared acceptance tolerances.

## Decays and limitations

For the analytic anchor, total width is 4.1119941e-15 GeV, diphoton branching fraction is 1.6567e-4, and cτ is 47.99 mm. The JSON records partial widths and branching fractions for the supported channels. Native diphoton diagnostics export per-fermion, W, and charged-Higgs terms, signed amplitudes, running-mass inputs, QCD settings, and loop width. Independent component and width reconstruction passes. The appendix pole-mass LO width differs from the native running-mass plus top-QCD width by about 8.2% at this anchor; that scheme comparison remains `INCONCLUSIVE`. When QCD-off disables the legacy production diphoton channel, its width is `NOT_TESTED` and a separate loop diagnostic is retained. Decay widths and lifetime are diagnostic, not validated phenomenology.

Displaced-photon selection and experimental exclusions are `NOT_TESTED`. No benchmark is listed in `validated_benchmarks.json`. The campaign rebuilt the canonical 2HDMC library and additive bridge with all five library translation units; existing `DihiggsPointV2Evaluator` and `Lambda1EvaluatorV2` executables retained their baseline SHA256 values, and existing legacy calculator executables were not relinked. A campaign-local evaluator was compared against the baseline evaluator at historical 450/500 GeV and an active-mass anchor, with exact CSV equality.

## Pilot-wide calculator agreement

The campaign now contains an identity-bound serial comparison over all 300 T1 and 90 active-mass pilot points at 50, 80, and 120 digit construction precision through legacy, explicit, and analytic calculator routes (3510 records total). Each successful constructor record includes all λ₁…λ₇ and Z₁…Z₇, backend double inputs, residuals, the four complete actual-backend scattering spectra and independent spectra, signed couplings, and widths/branching fractions/lifetime. The exact constructor failure reason is retained per route/precision record. The complete results are in `calculator_scan_agreement.jsonl`; status and maximum spectrum residuals are in `calculator_scan_summary.json`. These constructor-agreement labels are not physical-validation statuses. The scan shows analytic states assigned and phase-mapped from the actual backend spectrum; constructor-agreement statuses include per-observable closure checks. The native diphoton audit compares each fermion, W, and charged-Higgs term and the running-mass/QCD loop width. Default evaluator CSV rows are unchanged at historical450, historical500, and an active-mass representative. These results do not certify global extrema or physical boundaries.
